The World Wide Web — Generations, Protocols and Architecture

1. Who invented the web

The World Wide Web was invented by Sir Tim Berners-Lee in 1989. He was not trying to build a consumer product — he was looking for a new way for scientists to share data with each other.

2. The generations of the web

Web 1.0 — 1991 to 2001
The early stage of the World Wide Web, characterised by static web pages with linear content, limited user interaction and one-way communication.
Web 2.0 — post-2001
Marked by the emergence of dynamic web pages, rich media content and interactive platforms such as social media. Bandwidth improved over this period as well.
Web 3.0 — the Semantic Web
The evolution of the web into a semantic, interconnected data space, where advanced algorithms and new standards allow machine processing of content — leading to smarter search engines and similar capabilities.

Limitations of Web 1.0

  • Pages were static — the content did not change or respond.
  • Users could not interact with the sites; communication ran one way only.
  • Content was linear, with no user-generated contribution.

3. URL

URL — Uniform Resource Locator

A standard way of easily expressing the location and data type of a resource. It generally takes the form protocol://address, where the protocol is something like HTTP, FTP or telnet, and the address is the server name of the given resource.

4. HTTP

HTTP — Hypertext Transfer Protocol

A set of rules for exchanging files — text, graphics, images, sound, video and others — on the World Wide Web, connecting computers together over the web.

In practice, HTTP is the protocol responsible for how the web server and the web user communicate: it is the agreed set of rules for exchanging files between the client and the server. The client sends a request, the server sends back a response.

Spelling

It is hypertext transfer protocol, not “transform”. Easy mark to drop.

5. How the internet works, in 7 steps

What happens between typing an address and seeing the page:

  1. You — you type www.google.com into your browser.
  2. DNS — translates www.google.com into an IP address such as 100.120.12.3.
  3. ISP — your internet service provider (such as STC) connects you to the web and sends the request onward.
  4. NAP — if needed, a network access point helps exchange traffic between ISPs, routing the data between your ISP and the web server.
  5. HTTP — your browser uses HTTP to request the Google homepage.
  6. TCP/IP — Google's server sends the page back in packets, and IP makes sure they reach you.
  7. You — the Google homepage appears on your screen.

6. HTML

HTML — Hypertext Markup Language

A tagging language used to compose documents that will be viewed by a web browser. It was adopted so that no matter which computer platform someone is using, the browser knows how to display the web document.

7. Client and server

Client
The requesting program in a client/server relationship — for example, the user of a web browser making a request.
Server
In general, a computer program that provides a service to other computer programs, on the same computer or on other computers.
Web server
Stores and transmits web documents. It uses the HTTP protocol to connect to other computers and distribute information. Examples: Apache, Nginx, IIS.

8. Web pages, sites and hosting

Web page
A mixture of text, graphics, sound and animation in HTML format, making information accessible in an easy-to-understand form over the internet.
Website
A collection of web pages connected by clickable hypertext links.
Website hosting
After a website has been designed it must be stored on a computer that can be reached through the internet and the World Wide Web. That storage and service is hosting.

9. Domains

Domain

On the internet, a domain is a registration category identifying a geographic area or a purpose.

10. FTP

FTP — File Transfer Protocol

The standard used to transfer files over the internet. It allows you to copy any kind of computer file from one computer to another.

11. Protocols and TCP/IP

Protocol
A set of rules and standards governing how data is transported across a network — the rules that determine how the internet handles the message packets flowing over it.
TCP/IP — Transmission Control Protocol / Internet Protocol
A set of protocols developed to allow cooperating computers to share resources across a network. It is the foundational suite of communication protocols used to connect devices over the internet. TCP handles breaking data into packets and reassembling them reliably; IP is the addressing part — where the data is going.

12. Intranet and extranet

Coverage Note

Intranet and extranet appear in Tutorial 2 but are not covered in these notes. The definitions below come from the tutorial, not from the summary — check the original slides if you want more detail.

Intranet
A private internal network belonging to an organisation, used by its own employees. It is not open to the public.
Extranet
A private network that the organisation shares with third parties — clients or partners — for example in order to present its products or services to them. It is an intranet that has been extended outward to selected outsiders.

The distinction is simply who is allowed in: intranet = employees only; extranet = employees plus selected external partners; internet = everyone.

13. How to access the internet and the web

To get onto the internet you need three things:

  1. A device — a computer, phone or similar.
  2. An ISP — an internet service provider, which supplies the physical connection.
  3. A modem or router at your location, connecting your device to the ISP.

To reach the web on top of that, you additionally need a web browser and either the domain name or the IP address of the site you want to visit.

14. Firewalls

Firewall

A program — usually running on an internet gateway server — that protects the resources of one network from users on other networks. It is used to prevent outsiders from reaching your own private data resources.

Firewalls can exist as dedicated hardware, as software on a machine, or as a managed service.

The eight types of firewall

The eight firewall types and what each one filters on
TypeWhat it does
Packet filteringDepending on how the firewall is configured, you decide which packets of data are allowed to flow through the network.
ProxyActs as an intermediary between a recipient and an external system, which hides your system's IP address from attack.
InspectionInspects each packet flowing through it and decides whether to drop it.

Domain namesThe administrator can block access to particular websites, or allow only certain ones.
ProtocolFor each system on the network, you decide which services to permit.
PortsA service can run on any port, so for tighter control you can restrict services to specified ports.
