# Fuji San · فوجي سان — web menu

Mobile-first static web menu with three designs on the same page: **Sumi** (dark ink),
**Washi** (Japanese paper, light) and **Ai** (indigo with cream cards). No framework, no
build step on the server, no external JS.

```
index.html          generated by build.py (full menu pre-rendered, CSS inlined)
styles.css          the stylesheet for all three themes (source; build.py inlines it)
app.js              theme switcher, active-chip highlighting, live re-render from menu.json
data/menu.json      ALL menu content: sections, items, prices, calories, contact
img/                product photos (WebP), logos (logo-ink* = Washi), wave tiles, favicons
fonts/              self-hosted WOFF2 subsets (Arabic + Latin, Japanese used chars)
build.py            menu.json -> index.html (Python 3, standard library only)
tools/check_prices.py   cross-checks menu.json against the Sumi PDF
tools/make_fonts.py     regenerates the font subsets
_headers            Cloudflare Pages cache headers
site.webmanifest
```

## Themes

Open the page and use the small «اختر الثيم» pill in the top-left corner to switch
between «سومي» (Sumi), «واشي» (Washi) and «آي» (Ai). Each theme has a shareable link:

- `…/?theme=sumi`
- `…/?theme=washi`
- `…/?theme=ai`

The theme is chosen before the page paints: the `?theme=` link wins, then the visitor's
last choice (saved in the browser), then `DEFAULT_THEME`. Switching keeps the reader on
the same dish.

**After the client approves a theme**, edit the two lines at the top of `app.js`:

```js
const SHOW_SWITCHER = false;
const DEFAULT_THEME = "washi";   // the approved theme: "sumi" | "washi" | "ai"
```

then run `python3 build.py` and push. With the switcher off everyone sees
`DEFAULT_THEME` (old `?theme=` links and saved choices are ignored), and the build also
sets the browser colour and `site.webmanifest` colours to that theme.

How it works: one HTML structure for all themes; `<html class="theme-…">` selects the
look. `styles.css` holds the Sumi rules (every colour and font is a variable) followed by
a Washi block and an Ai block that override the variables and add their own touches.
Fonts for all themes are declared, but a browser only downloads the ones the active theme
uses; the logo variant and wave pattern are CSS backgrounds scoped to the theme, and the
closing image is set by script, so each theme only fetches its own files.

## Editing the menu

1. Edit `data/menu.json`. A price change is one line, e.g. `"price": 29.5`.
2. Run `python3 build.py` to regenerate `index.html`.
3. Commit and push — Cloudflare Pages redeploys automatically.

If you forget step 2 the live page still shows the new data: `app.js` notices that
`menu.json` no longer matches the hash baked into `index.html` and re-renders from it.
Re-running `build.py` is still the right thing to do (search engines and no-JS visitors
see `index.html`).

Item fields:

| field    | meaning |
|----------|---------|
| `id`     | unique slug, also the photo file name |
| `ar`, `en` | Arabic name, English name |
| `desc`   | English description (shown muted under the names) |
| `price`  | number in SAR, VAT included |
| `options`| optional, several prices (e.g. Saudi Mocktail: `كوب` 15 / `جك` 40) |
| `pcs`    | piece count or `null` (2 → "قطعتان", 3–10 → "N قطع", 11+ → "N قطعة") |
| `cal`    | calories |
| `photo`  | `img/<id>.webp` or `null`; `hero` = larger photo used in featured cards |
| `level`  | `foothill` / `mid` / `summit` / `null` — Fuji level; items are grouped by it |
| `isNew`  | shows the red "جديد · New" badge |

The "New" section lists `{"ref": "<id>"}` entries pointing at items elsewhere, so each
price lives in exactly one place. Sections with `"layout": "featured"` render as large
cards; `"list"` sections render as lists (2 columns from 900 px).

Contact buttons: fill `contact.phone` (`+9665…`), `contact.whatsapp` (digits with
country code) and `contact.instagram` (handle). Empty fields render as dashed
placeholders. Set `site.url` to the live address once you have it so Open Graph and
canonical links are absolute.

New photo: transparent WebP, max ~400 px wide (800 px for featured cards), named
`img/<id>.webp`. `build.py` reads the width/height from the file automatically.

## Where it lives

This site is the `fujisan/` folder of the `xlBABA/0xmyth` repository. That repository's
GitHub Pages workflow publishes it at `https://xlbaba.github.io/0xmyth/fujisan/` on every
push to `main` (all paths are relative, so it works in a subfolder).

## Deploy on Cloudflare Pages

> In the `0xmyth` repository the site is in a subfolder: set the build output directory
> to **`fujisan`** instead of `/` below.

1. Put this folder in a GitHub repository and push it. The `.gitignore` keeps the
   source PDFs out of the repo so they are not published with the site.
2. Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** →
   **Connect to Git** (Import an existing Git repository) → pick the repository.
3. Build settings:
   - Framework preset: **None**
   - Build command: *(leave empty)*
   - Build output directory: **`/`**
4. **Save and Deploy**. The site goes live at `https://<project>.pages.dev`, and every
   push to the production branch redeploys it (other branches get preview URLs).

`_headers` sets caching: HTML and `menu.json` always revalidate, fonts are cached for a
year, images for a week. Cloudflare compresses HTML/JS/JSON automatically.

### Custom domain (later)

1. In the Pages project → **Custom domains** → **Set up a custom domain** → enter e.g.
   `menu.example.sa`.
2. If the domain's DNS is on Cloudflare, the record is created for you. If not, add a
   `CNAME` at your DNS provider: `menu` → `<project>.pages.dev`. (An apex domain such as
   `example.sa` needs its DNS zone on Cloudflare.)
3. Wait for the certificate to become **Active**, then set `"site": {"url": "https://menu.example.sa"}`
   in `data/menu.json`, run `python3 build.py`, and push.

## Fonts

Subsets of the Google Fonts originals (SIL Open Font License). Only the active theme's
heading font is preloaded.

| theme | fonts |
|-------|-------|
| Sumi  | Reem Kufi 600, IBM Plex Sans Arabic 400/500/600, Cinzel 600–700, Noto Serif JP 500 |
| Washi | Amiri 700, Noto Naskh Arabic 400–700, Cormorant Garamond 700 + Italic 500, Jost 400–500, Noto Serif JP 600 |
| Ai    | Baloo Bhaijaan 2 600–800, IBM Plex Sans Arabic 400/500/600, Noto Sans JP 500 |

To regenerate (e.g. after adding new Japanese characters), download the TTFs into one
folder and run `pip install fonttools brotli && python3 tools/make_fonts.py <folder>`.
